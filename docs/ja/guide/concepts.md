# 基本概念

PageFlow はアプリケーションのルートと遷移先を、探索できるグラフに変換します。次の五つを理解すれば、画面全体を簡単に使えます。

## ページ

ページは PageFlow が描画できる一つの具体的なルートです。静的ルートはすぐに利用でき、動的ルートは代表的なパラメーター値を設定すると描画できます。

各ページにはタイトル、パス、プレビュー、サムネイル、リンク、関連テストを持たせられます。クエリ文字列やハッシュは、別のルートを増やさずに、より具体的な遷移位置を保持します。

## ナビゲーションリンク

リンクは、あるページから別のページへの方向付きの関係です。PageFlow は対応ルーターのリンク、同一オリジンのアンカー、リテラルなプログラム遷移、ブラウザー履歴、`data-pageflow-to` などの明示的なヒントを検出します。

実行時に計算される遷移先は、該当する操作が行われるまで判明しない場合があります。

## ホットスポット

ページを選択すると、既知の遷移を発生させる要素が強調されます。ホットスポットはプレビューとグラフを結び、二つのルートの関係だけでなく、実際の UI のどこから遷移するかも示します。

## プレビューとサムネイル

選択中のページは同一オリジンのライブ iframe で表示します。周辺ページにはキャプチャ済みプレビューを使い、キャンバスの応答性を保ちます。古いページを更新している間も、キャッシュ済みサムネイルは表示されます。

## ルートグループ

大きなルートツリーはデッキにまとめられます。デッキを開いて子階層を確認し、パンくずで上位階層へ戻れます。ページ同士の関係を失わずに表示上のノイズを減らします。
