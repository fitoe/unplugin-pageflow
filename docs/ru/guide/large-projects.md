# Крупные проекты и кэширование

PageFlow не отображает каждый маршрут как активный документ одновременно. Стратегия рендеринга и кэширования ограничена, поэтому большие графы остаются удобными для изучения.

## Рендеринг viewport

Монтируются только близкие DOM-превью и объекты сцены LeaferJS. Дальние страницы используют компактное представление. Одна выбранная страница переводится в активный iframe.

## Уровни миниатюр

Близкие страницы могут использовать подробные превью. Дальние используют компактные WebP-миниатюры, а длинные страницы можно разделить на плитки, монтируемые в viewport. Устаревшие миниатюры остаются видимыми во время записи новых.

## Очередь снимков

Перед снимком PageFlow ждёт загрузки шрифтов и изображений, а также стабилизации DOM. Работа выполняется по одной странице с приоритетом выбранной и видимых страниц.

## Раскладка и поиск

Графы более чем из 1 000 страниц могут перенести раскладку в Worker. Пространственный индекс находит видимые страницы без обхода всего графа при каждом обновлении viewport.

## Расположение кэша

Постоянные миниатюры хранятся в:

```text
.unplugin-pageflow/cache
```

Кэши в памяти и на диске используют фиксированные лимиты LRU. Каталог является удаляемым результатом разработки; его можно очистить для полностью новой записи.

## Практические рекомендации

- Группируйте маршруты по осмысленным сегментам пути.
- Указывайте стабильные примеры динамических параметров.
- Делайте превью предсказуемыми с помощью фикстур.
- Используйте сигнал готовности для долгих асинхронных страниц.
