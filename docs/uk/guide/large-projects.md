# Великі проєкти та кешування

PageFlow не відображає кожен маршрут як активний документ одночасно. Стратегія відображення та кешування має фіксовані межі, тому великі графи залишаються зручними для перегляду.

## Відображення області перегляду

Монтуються лише найближчі DOM-перегляди та об’єкти сцени LeaferJS. Віддалені сторінки використовують компактне подання. Одна вибрана сторінка переводиться в активний iframe.

## Рівні мініатюр

Сусідні сторінки можуть мати деталізований перегляд. Віддалені сторінки використовують компактні WebP-мініатюри, а довгі сторінки можна розділити на плитки, що монтуються в області перегляду. Застарілі мініатюри залишаються видимими, доки створюються нові.

## Черга знімків

Перед створенням знімка PageFlow очікує завантаження шрифтів, зображень і стабілізації DOM. Сторінки обробляються по одній, із пріоритетом для вибраних і видимих сторінок.

## Компонування та пошук

Для графів із понад 1 000 сторінок компонування може виконуватися у Worker. Просторовий індекс знаходить видимі сторінки без сканування всього графа під час кожного оновлення області перегляду.

## Розташування кешу

Постійні мініатюри зберігаються в:

```text
.unplugin-pageflow/cache
```

Кеші в пам’яті та на диску використовують фіксовані LRU-ліміти. Це тимчасовий результат розробки, який можна видалити, коли потрібне повністю нове захоплення.

## Практичні поради

- Групуйте маршрути за змістовними сегментами шляху.
- Надавайте стабільні приклади динамічних параметрів.
- Робіть сторінки попереднього перегляду детермінованими за допомогою тестових даних.
- Для тривалих асинхронних сторінок використовуйте сигнал готовності.
